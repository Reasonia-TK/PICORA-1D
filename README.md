# PICORA-1D

1D PIC-MCC のプラズマシミュレーションアプリです。

## 機能

- 1d3v PIC、一様格子、CIC 電荷配置、三重対角 Poisson、leapfrog 粒子追跡
- 左右電極の DC・複数 RF・CSV 任意波形、二次電子放出、Fowler–Nordheim 放出、阻止コンデンサによる自己バイアス
- 外部回路とPICの連成、回路図の配置・配線・素子編集、回路の電圧・電流・電力・エネルギー履歴
- MCC 衝突、LXCat 断面積インポート（プリセットなし）
- 単一条件の CPU 並列計算（既定で有効、スレッド数は自動または手動指定）
- 実行、停止、同じ粒子状態からの続き、進捗、安定性警告、収束判定
- ライブ場・電子位相空間、時間平均・RF 位相別プロファイル、EEDF/EEPF、壁 IEDF、シースと FFT、収束結果
- 物理量一覧から全診断量・物理条件・定数を選択してプロット（検索、分類、最大4量の同時表示、単位・定義・未取得理由）
- 1D パラメータの逐次掃引、設定と結果の JSON 保存・読み込み、グラフデータの CSV 出力
- ライト・ダーク・OS 追従テーマ（画面上部から切替、選択を保存）
- 直接編集と設定ウィザードの切替（設定を共有、モード選択を保存）

計算は CPU で動作します。粒子更新・CIC 電荷配置・補間・診断モーメントを Numba で並列化し、MCC の一部も JIT で高速化します。

## セットアップ

開発環境: Windows、Python 3.11 以上、uv、Node.js、Rust/MSVC（デスクトップ版用）。

```powershell
cd PICORA-1D
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
```

## 起動

`PICORA-1D.cmd` をダブルクリックするか、以下を実行します。デスクトップ版は Python バックエンドも自動起動し、閉じると停止します。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start.ps1
```

Rust を使わずブラウザーで起動する場合:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start.ps1 -Browser
```

ブラウザー版の URL は `http://127.0.0.1:8321` です。終了はターミナルで Ctrl+C。
UI の開発サーバーを使う場合は、`backend` で `uv run uvicorn es_sim.server:app --host 127.0.0.1 --port 8321`、別ターミナルの `ui` で `npm run dev`（ポート1425）を実行します。

## 操作

初回は軽量な条件で画面と計算を確認できます。放電条件は画面または JSON から設定し、MCC を使用する場合は LXCat インポートで電子・イオンの断面積を設定してください。

画面上部の「設定モード」で「直接編集」と「ウィザード」を切り替えます。既定は起動してすぐに編集・実行できる「直接編集」です。選択したモードは次回起動時にも使われます。

ウィザードでは、格子・初期状態、電極・外部回路、背景ガス・衝突、計算時間・CPU、診断・分布、確認・実行の順に「次へ」で進みます。入力途中・不正な数値は先へ進む前に確認し、「戻る」や前の手順から修正できます。外部回路は電極の手順で編集・検証できます。最終画面の「設定を確定して実行」で計算を開始し、結果画面を表示します。「ウィザードで再設定」で設定フローに戻れます。「直接編集へ」でいつでも従来の画面に移れます。切替によって設定や実行結果は消えません。

「CPU 並列計算」は既定で有効です。スレッド数が空欄なら CPU に合わせて自動選択し、手動指定もできます。粒子数が少ない演算は並列起動の負荷を避けて逐次処理します。MCC の乱数処理、Poisson、壁処理などは逐次部分を含むため、全処理が指定スレッド数に比例して速くなるわけではありません。Numba が使えない環境では理由を表示して NumPy の逐次計算に戻ります。

並列計算の電荷配置は専用の作業配列で加算競合を防ぎます。縮約の加算順序が逐次計算と異なるため、微小な丸め差が生じます。「CPU 並列計算」を無効にすると、元 ES-Sim と同じ NumPy の演算経路を使用します。パラメータ掃引は各条件を順番に実行し、各条件内で CPU 並列化します。

条件を設定して「実行」を押すとライブ表示が更新され、完了後に解析結果が表示されます。「停止」で途中の結果を得られ、「続き」で同じ粒子状態から計算を延長できます。
保存 JSON の結果は再表示できますが、保存ファイルには全粒子状態を含まないため、アプリを再起動した後の計算再開には使えません。

設定欄にない高度な設定は JSON 編集から変更できます。物理モデル、単位、既定値は元ソルバーと同じです。
既定の時間平均は最後の25%、RF 位相分解は設定されたビン数を使用します。精密な比較には十分な定常化・粒子数・時間平均が必要です。

「物理量一覧」では電位・電場・電荷密度、電子とイオンの密度・3成分速度・電流密度・熱温度、エネルギー・電力、Debye 長とプラズマ角周波数、粒子状態、壁入射、衝突・電離・放出、回路の電圧・電荷・容量、分布・FFT・収束、MCC の断面積・衝突周波数、実際に使用した物理定数を選択できます。固定条件と定数は水平線として表示します。「表示を固定」で最大4量を並べ、各グラフを CSV に出力できます。

粒子プロットは各種最大2000点の試料、追加の物理履歴は最大約2000点に間引きます。壁フラックス・入射電力・イベント頻度はサンプル間の平均です。leapfrog の位置・速度・場は時刻がずれるため、各量の定義に時刻を明記しています。無効なモデル、未観測の位相ビン、未定義の Debye 長は欠測として扱います。旧保存結果に追加量がない場合は新しく計算してください。

## 外部回路

選択した素子は「90° 回転」または **Ctrl+R** で時計回りに90°回転します。端子と接続配線も回転に追従し、元に戻す・やり直しに対応します。数値編集欄にフォーカスがある場合もCtrl+Rを使用できます。Ctrl+R・Ctrl+Shift+RによるWebViewの再読み込みは抑止し、回路タブ以外や計算中は回転しません。

「外部回路」タブで素子を追加し、端子を順に選んで配線します。回路図上の交差だけでは接続されません。同じ端子から複数の配線を伸ばして分岐を作ります。PIC部品の `left`・`right` は計算領域の左・右電極です。

抵抗、キャパシタンス、インダクタンス、詳細ダイオード、同軸ケーブル（4端子またはシールド接地）、時間制御スイッチ、DC・正弦波・パルス・PWL電圧源、接地を使えます。部品を選ぶと数値を編集でき、指数表記も入力できます。配置移動・回転・複製・削除と、配線の削除、元に戻す・やり直しに対応します。設定JSONには素子の数値、配線、座標、回転、ノード名を保存します。未配線の編集中回路も保存して再編集できます。

キャパシタの初期電圧・インダクタの初期電流は、空欄ならDC初期解を使います。数値を指定すると0も含めて初期状態に固定します。理想電圧源などと矛盾する初期値はエラーになります。正弦波はオフセット・振幅・周波数・位相・遅延、パルスとPWLはそれぞれの指定電圧を使います。DC欄の値をパルス・PWLへ加算しません。

「外部回路連成」を有効にして両PIC端子とGNDを配線し、「回路を検証」で接続と初期状態を確認します。連成時の駆動は回路図の電圧源で指定してください。従来の電極DC・RF・CSV電圧は使用せず、SEE・FN放出は使用します。従来の阻止コンデンサ設定との併用はできません。阻止コンデンサを含む回路は回路図で組み立てます。

電極面積 [m²] によってPICの面積あたり電荷・電流をC・Aに換算します。各場更新で、空間電荷の誘導電荷、電極容量行列、前区間の壁吸収・放出電荷を回路の節点方程式に含めて電極電圧を解き、その電圧でPoissonを1回解きます。回路には後退Eulerを使います。停止や「続き」ではキャパシタ・インダクタ・ダイオード・線路の状態と未反映壁電荷を保持します。

「物理量一覧」の外部回路カテゴリから、全ノード電圧、素子の電圧・電流・瞬時電力・蓄積エネルギー、PIC端子の伝導・変位・全電流、電極電荷を表示できます。受動素子・電圧源の電流はp→nを正とし、電力は受動規約です。PIC端子の全電流は回路から電極へ流れる向きを正とします。場と粒子の時刻差、最終区間の未反映壁電荷を結果のmetadataに記録します。

同軸はTEM分割線路と基準周波数で合わせた受動損失近似です。4端子版も両端シールドを共通の理想基準として扱います。詳細ダイオードは接合電流、直列抵抗、逆降伏、接合容量、走行時間、温度依存を含む独自の数値モデルです。参考アプリのngspiceとビット一致するモデルではありません。急峻なパルス・高調波・線路伝搬を評価する場合は、時間刻みと線路分割数を変えて応答の収束を確認してください。モデルの定義・仮定は結果にも記録します。

## 確認

```powershell
cd backend
uv run python -m pytest
cd ..\ui
npm run typecheck
npm test
npm run build
```

元と抽出後のコアの比較はルートで `uv run --project backend python scripts\verify_extraction.py`。
検証内容と結果は `reports/extraction-regression.json` に記録します。
DC、Ar RF、阻止コンデンサと二次電子放出、Fowler–Nordheim 放出の4条件で、逐次モードの元ソルバーに存在する結果・ライブ表示・粒子状態・乱数状態・継続計算をビット単位で比較します（追加診断と実行時間の値を除く）。並列モードの電荷保存・逐次計算との差・スレッド数による再現性は専用テストで確認します。

同梱バックエンドの確認は `uv run --project backend python scripts\verify_backend_bundle.py`。起動、Numba/MCC、停止、継続、全種類の素子を含む外部回路の検証とPIC連成を確認し、`reports/bundle-smoke.json` に記録します。

0.3.0 の確認結果: バックエンド120件、UI52件のテストが通過し、型チェック・UIビルド・同梱バックエンドの確認も通過しました。RCの解析解、RLCの応答、ダイオードの電流・降伏・容量・温度依存、同軸の損失と伝搬、電極での電荷保存、停止・継続を検証しています。元ソルバーとの4条件の比較はビット一致を維持しています。画面では回路の配置・端子配線・詳細数値編集・入力途中の検出・連成実行・電極電圧と電流の表示、ライト・ダークテーマを確認しました。

0.2.0 の確認結果: バックエンド84件、UI33件のテストが通過。Numba 無効時は並列専用テスト5件を除く14件が通過しました。このPCの4スレッド・128セル・無衝突100ステップの計測では、5千粒子/種で約2.1倍、2万で約2.1倍、20万で約6.6倍高速化しました（初回JITを除外、追加診断を含む、UI通信を除く）。計測値は `reports/parallel-benchmark.json` に保存しています。

## 配布ビルド

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_app.ps1
```

CPU バックエンドと実行環境を同梱した Windows インストーラーを `ui\src-tauri\target\release\bundle\nsis\` に生成します。
配布版は Python、uv、Node.js、Rust のインストールが不要です。配布版のバックエンドは空きポートを自動選択します。

## 構成とライセンス

`backend/` は 1D 計算と FastAPI、`ui/` は React と Tauri、`scripts/` は起動・ビルド・抽出検証です。
Python は `pyproject.toml` と `uv.lock`、UI は `package-lock.json`、Rust は `Cargo.lock` で依存を固定します。
テーマの色は `ui/src/theme.css` に集約します。
